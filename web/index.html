Overview

An agent acting for someone else: three patterns

Each pattern answers one question: whom does the agent act for, and who decides it may? Hover a line for the detail.

Common to all three: AgentCore Runtime runs the agent, AgentCore Identity gets its tokens (no Okta code or key in the agent), and every token names the person or app the agent acts for (sub) and each actor on the way (act).

Why Pattern B

Where Pattern A stops working

Pattern A is simpler, and enough when every resource is protected by your own Okta org. These are the cases it can't handle. Hover a card for the detail.

Pattern B is the same delegation (the token still names Ada and the agent) but built for these: an Okta AI agent, an ID-JAG from the IdP, and a JWT bearer grant at the resource's own authorization server.
